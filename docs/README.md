The documentation site for [Arlecchino](https://github.com/The1fEst/Arlecchino), a terminal UI
framework for .NET. Published at **https://the1fest.github.io/Arlecchino/**.

## Layout

Paths are relative to this folder, the root of the site.

| Path | Holds |
|---|---|
| `docs/` | The written pages, as plain CommonMark |
| `docs/api/` | The API reference, generated by `npm run api` and not committed |
| `apidocs/ApiDocs.cs` | The generator that writes `docs/api` from the built assemblies |
| `src/` | The landing page and the theme |
| `static/img/` | Brand assets and screenshots |
| `sidebars.ts` | The order the pages appear in |

## Running it

The API reference is generated from the built framework, so build it once from the repository root:

```bash
dotnet build Arlecchino.slnx -c Release
```

Then, in this folder:

```bash
npm install
npm run api
npm start
```

Node 20 or newer. `npm run build` produces the static site in `build/`, and `npm run serve` shows what
was built. Both need `npm run api` to have run first, since the sidebar's API section reads `docs/api`.

## Regenerating the API reference

`npm run api` is `dotnet run apidocs/ApiDocs.cs -- --repo .. --out docs/api`. It reads the Release
build of each published assembly under `src/`, so the library must be built first, and it needs the
.NET 10 SDK. It deletes and rewrites `docs/api` every time.

The reference is generated from the code being built, and is not committed.

## Writing a page

Pages are CommonMark — `markdown.format` is `md`, not MDX — with front matter for the title and the
description. Add the new page to `sidebars.ts`; nothing is picked up automatically except `docs/api`.

Links between pages are relative and keep the `.md` suffix, so they work both on the site and when
reading the file on GitHub:

```markdown
See [Layout](layout.md) and [`Surface`](api/arlecchino.rendering/Surface.md).
```

The build runs with `onBrokenLinks: 'throw'`, so a link that does not resolve fails it.

## Deploying

The `docs` workflow (`.github/workflows/docs.yml`) builds the site for every pull request and every push
to `master` that touches `docs/`, so a broken link or a broken generator fails there, before a release.
It publishes only when the release workflow calls it once the packages are out, passing the tag, so the
reference is generated from the code that was released.

To publish without a release, run the `docs` workflow by hand from the Actions tab. It builds the branch
it is run on, unless a tag is given as `ref`.

Set **Settings → Pages → Source** to *GitHub Actions* once for the repository.
